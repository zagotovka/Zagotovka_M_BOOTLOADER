# Zagotovka_M_BOOTLOADER

## Bootloader — двухбанковый OTA-загрузчик

Загрузчик находится в папке `Bootloader/` и занимает первые **128 КБ** Flash-памяти (`0x08000000`–`0x0801FFFF`). Он отвечает за выбор и запуск основного приложения, а также за механизм безопасного OTA-обновления через переключение банков.

### Карта памяти Flash

| Область | Адреса | Размер | Назначение |
|---------|--------|--------|------------|
| Bootloader | `0x08000000` — `0x0801FFFF` | 128 КБ | Загрузчик (этот код) |
| Bank A | `0x08040000` — `0x080FFFFF` | 768 КБ (сектора 5–7) | Основное приложение |
| Bank B | `0x08100000` — `0x081BFFFF` | 768 КБ (сектора 8–10) | Резервный банк для OTA |
| Sector 11 | `0x081C0000` — `0x081FFFFF` | 256 КБ | Хранилище настроек (94 слота) |

### Как это работает

1. При включении загрузчик считывает настройки из **Sector 11** (кольцевой буфер из 94 слотов с CRC32-проверкой).
2. На основании полей `ota_pending`, `ota_state`, `ota_active_bank` и `ota_boot_retries` определяет, какой банк запускать.
3. Выполняет `jump_to_app()` — полную деинициализацию HAL, очистку NVIC/SysTick, переключение векторов прерываний (SCB->VTOR) и передачу управления приложению.

### Логика выбора банка

```
ota_pending == 0 (нет обновления)?
  └─ Запуск ota_active_bank (0 → Bank A, 1 → Bank B)

ota_pending == 1 (идёт обновление)?
  ├─ ota_state == 3 (COMMITTED)
  │   └─ Запуск ota_active_bank — обновление подтверждено
  │
  ├─ ota_state == 2 (ROLLBACK)
  │   └─ Откат на Bank A, сброс OTA-флагов
  │
  └─ ota_state == 0 или 1 (TESTING)
      ├─ boot_retries >= 3
      │   └─ Откат на Bank A — приложение не запускается
      └─ boot_retries < 3
          ├─ Инкремент boot_retries
          └─ Запуск Bank B для тестирования
```

### Состояния OTA (ota_state)

| Значение | Название | Описание |
|----------|----------|----------|
| 0 | No data | OTA-данных нет, используется обычный банк |
| 1 | First boot | Первая загрузка нового образа после OTA |
| 2 | Uncommitted | Запрошен откат (по команде приложения) |
| 3 | Committed | Обновление подтверждено, откат невозможен |

### Защита от «кирпича»

- **Автооткат**: если новое приложение не запускается (зависает, глючит), после 3 неуспешных перезагрузок загрузчик автоматически откатывается на предыдущий рабочий банк (Bank A).
- **Ручной откат**: приложение может запросить откат, записав `ota_state = 2` в настройки. При следующей перезагрузке загрузчик переключится на Bank A.
- **Подтверждение**: после успешного запуска приложение должно вызвать `mg_ota_commit()`, установив `ota_state = 3`. Только после этого обновление считается завершённым.

### Как прошить загрузчик

1. Прошейте `Bootloader/main.c` через STM32CubeIDE (конфигурация для NUCLEO-F767ZI).
2. Затем прошейте основное приложение в **Bank A** (`0x08040000`).
3. Загрузчик автоматически определит банк и запустит приложение.

> **Важно:** загрузчик прошивается отдельно от основного приложения. Они используют разные линковочные скрипты (`STM32F767_BOOT.ld` vs `STM32F767ZITX_FLASH.ld`).
